XSS 解题方法笔记1

一、核心思路

找到输入点 → 定位输出点 → 判断输出上下文 → 分析过滤规则 → 按上下文语法构造 payload → 验证。

所有绕过技巧都围绕一条主线：输入被拼进页面的哪个语法位置，就按那个位置的规则构造逃逸。

二、步骤

2.1.定位输入点

凡是服务器会读取并写回页面的客户端数据，都可能是注入点。常见类型：

  • URL 查询参数（最常见）
  • POST 表单字段
  • HTTP 请求头：Referer、User-Agent、X-Forwarded-For 等
  • Cookie 值
  • 上传文件的文件名、文件内容（如图片 exif 信息）

识别技巧：字段名本身是线索。 例如页面源码中出现名为 t_ref 的字段，拆解即 Referer 缩写，说明注入点在 Referer 头；t_ua 对应 User-Agent；Cookie 中名为 user 的字段被输出，说明注入点在 Cookie

2.2.定位输出点

方法：提交独特标记串

提交一串独一无二的字符串（如 zzztest888），在响应页面中搜索它出现的位置。随机字符串避免与页面既有内容混淆，确保搜索到的位置就是真实反射点。

关键细节

必须查看原始 HTML 源码，而非浏览器渲染后的页面。 浏览器渲染会执行标签、展开属性，掩盖真实结构。源码才能反映输入被拼进了什么语法环境。

一个输入可能存在多处输出点，需逐一排查。 例如同一个参数同时被输出到 <h2> 正文和 <input value> 属性中，前者可能转义了尖括号，后者却原样输出。找到标记串后，应搜索源码中每一处出现位置，分别评估攻击可行性，不可只看第一处就下结论。

2.3.判断输出上下文

输出位置决定攻击方式。按实战中出现的环境分类：

1. 标签之间的正文

输出形如 <div>输入</div>。直接提交 <script>alert(1)</script> 即可执行，这是最理想的情况。

2. 属性值内部（有引号）

输出形如 <input value="输入">。此时 <script> 被引号包裹，浏览器将其当作属性值文本而非标签，不会执行。

攻击方式：闭合 + 逃逸。 先用 "> 闭合 value=" 的引号，再撑破 <input> 标签，后续的 <script> 即成为独立标签被执行。

3. 尖括号被转义/过滤，引号仍在

无法书写 <script> 标签。改用事件属性，全程不需要尖括号。

例如 " onclick="alert(1)，闭合引号后拼上一个事件属性。浏览器将输入解析为标签上的合法事件属性，用户触发即执行。

常见事件属性：

  • onclick：鼠标点击
  • onmouseover：鼠标划过
  • onfocus：获得焦点（可配合 autofocus 自动触发）
  • onload：元素加载完成
  • onerror：加载失败时
  • oninput：用户输入时

事件属性种类多，逐一尝试总能找到未被过滤的。

4. 关键字被插入字符破坏

如 <script> 变成 <scr_ipt>、onclick 变成 o_nclick，即过滤器在关键字中插入 _ 破坏完整性。

应对思路：换一条过滤器未设防的路。 若过滤器只针对 <script 和 on*，则使用 javascript: 伪协议——它不需要 script 标签，也不需要事件属性。

5. 输出在 href / src 等 URL 属性中，且无法闭合

当引号被编码、事件属性被破坏、无法插入新标签时，注意一个事实：href 属性天生支持 javascript: 伪协议，不需要闭合、不需要新标签，只需让协议头完整存在于属性值内。

javascript: 伪协议本质：冒号后的内容不是资源地址，而是一段直接执行的 JavaScript 代码。载体包括 <a href>（点击触发）、<iframe src>（加载触发）等。

6. 输出在隐藏 input 中

输出形如 <input type="hidden" value="输入">。即使成功注入事件属性，hidden 元素不可见、不可点击、无法触发事件。

破解思路：利用 HTML 属性重复时浏览器只认第一个的规则。 注入 1" type="text" onclick="alert()"，浏览器先解析到 type="text"（可见文本框），源码中原有的 type="hidden" 被忽略，元素变为可交互。

7. 输出在前端框架指令中（DOM 型）

当服务器不直接拼接输出，而是前端框架（如 AngularJS）处理时，攻击思路转变为理解前端框架的指令语义。

例如 <span class="ng-include:输入">，ng-include 冒号后的内容是表达式，会被求值为加载地址。可令其加载一个存在反射点的页面，再通过该页面的参数注入恶意代码——DOM 型入口 + 反射型出口的组合拳。

8. 输出在无引号的属性值中

输出形如 <embed src=输入>，属性值无引号。

攻击方式：浏览器依靠空格判断属性值边界。 在输入中插入空格，即切断 src 值，空格后写的内容被浏览器解析为新的事件属性。

2.4.分析过滤规则

方法一：试探法

第一发：提交 <script>alert(1)</script>。 观察结果：

  • 弹窗 → 无过滤，结束。
  • 原样显示为文字 → 尖括号可能被转义或过滤，查看源码确认。
  • 源码中 < 变为 < → 转义（非删除），需寻找未转义的字符。
  • 部分内容消失 → 过滤（删除/替换），需判断删了什么。

第二发：查看源码中 payload 的变形。 每次变形都是过滤规则的线索：

  • <script> 变 <scr_ipt> → 在关键字中插字符。
  • href 消失、" 变 " → 过滤关键字 + 编码引号。
  • 空格全变 → 空格被替换为 HTML 实体。

第三发：针对性测试盲区。

  • 双引号被转义 → 测试单引号是否被转义（常见漏网）。

  • 关键字被过滤 → 测试大小写（HTML 对大小写不敏感，过滤器可能只匹配小写）。

  • 删除了一次 → 测试双写（删除后剩余部分重新拼接成完整关键字）。

方法二：读源码

拿到后端代码时，重点看三件事：

过滤还是转义。 两者本质不同：过滤删除/替换字符，存在双写、编码等绕过空间；转义将字符变成无害实体，需寻找未被转义的字符。

处理了哪些字符。 特别注意只转义一部分的情况——只转义双引号不转义单引号、只转义尖括号不转义引号，漏掉的那个字符就是突破口。

黑名单还是白名单。 黑名单（列出禁止内容）几乎总有绕过；白名单（只允许合规内容）只能寻找规则本身的漏洞。

核心原则

过滤器与浏览器是两套系统。 过滤器是纯字符串匹配，浏览器是 HTML 解析器。过滤器不认识的编码，浏览器可能认识——所有绕过本质都在寻找”过滤器眼中的字符串”与”浏览器眼中的语义”之间的缝隙。

2.5.构造 payload

  • 正文输出、无过滤 → <script>alert(1)</script>
  • 属性值内 → "> 或 '> 闭合引号，逃出属性后写标签或事件
  • 尖括号被干掉 → 事件属性（" onmouseover="alert(1)），不用尖括号
  • on 关键字被干掉 → javascript: 伪协议，不用 on
  • href 关键字被过滤 → 大小写混合（hRef）
  • 关键字被循环删除 → 双写（hrhrefef 删中间的 href 后拼回完整 href）
  • 引号被编码、只能留在 href 内 → 对 javascript:alert() 做 HTML 实体编码（过滤器不认实体，浏览器认）
  • 必须包含 http:// 才放行 → 将 http:// 塞进 JS 注释：javascript:alert(1)//http://，过滤器看到 http:// 放行，浏览器执行时 // 后全是注释
  • 空格被替换为 → 空格换成 %0a（换行符），浏览器解析标签时换行与空格等价
  • 输出在 hidden input → 闭合 value 后加 type="text"，利用属性重复认第一个的规则覆盖 hidden
  • 注入点在 Referer / User-Agent / Cookie → 思路不变，payload 放入请求头或 Cookie，用 Burp 改包发送
  • 注入点是文件内容（exif） → 构造带恶意 exif 的文件上传
  • 输出在前端 JS / 框架指令 → 读前端代码，理解拼接逻辑与指令语义

2.6.验证

触发条件

注入成功不等于弹窗，中间隔着触发环节。验证前先明确：所用事件需要什么触发条件？页面加载？鼠标划过？点击？自动聚焦？hidden 元素点不到、划不到，必须先把元素变为可见。

控制台报错

弹不出来时按 F12 查看 Console。引号未闭合、标签未写对等语法错误会直接体现在报错中，用于快速定位 payload 缺陷。

编码

在 URL 中传递 payload 时，空格、引号、尖括号、斜杠等特殊字符必须 URL 编码，否则可能被截断。换行符 %0a、回车符 %0d 就是靠编码塞进 URL 的。

三.工具

浏览器开发者工具（F12）

  • Elements：查看真实 DOM 结构与原始 HTML
  • Console：查看 JS 报错
  • Network：查看请求与响应
  • Sources：查看前端 JS 源码（DOM 型题目必需）

Burp Suite

  • 抓包改包：注入点在请求头、Cookie 时，浏览器无法直接修改，必须抓包
  • Repeater：同一请求反复测试不同 payload
  • Intruder：批量 fuzz 关键字与编码
  • Decoder：URL 编码、HTML 实体编码等转换

四、防御要点

  • 输出编码为主，输入过滤为辅。 输入过滤易绕过，输出编码按上下文精确处理才可靠。
  • HTML 文本上下文：实体编码 < > & " '（注意 htmlspecialchars 默认不转单引号，须加 ENT_QUOTES）。
  • 属性上下文：属性值必须加引号，并转义引号字符。
  • URL 上下文：URL 编码 + 协议白名单（只允许 http/https），黑名单拦 javascript: 总有编码绕过。
  • 事件属性：属性名用白名单，用户输入永远不能作为属性名。
  • DOM 操作：使用 textContent 替代 innerHTML，避免把不可信数据拼进可执行 API。
  • 纵深防御：Cookie 加 HttpOnly、响应头设 CSP 限制脚本来源、前端框架默认转义插值并慎用 v-html 类 API。
