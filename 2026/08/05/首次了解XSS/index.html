XSS跨站脚本攻击

什么是XSS?

xss就是攻击者在网页里注入恶意代码，浏览器误以为是正常代码并执行。

网页把「用户输入」当成「代码」执行了，而不是当成「普通文字」显示。

只要网页把输入的东西当成「代码」而不是「普通文字」来执行，就可能存在 XSS。

XSS 本质上是一种客户端攻击。

漏洞在前端代码里，恶意代码在用户浏览器里执行，最终受害的是打开网页的用户。

XSS 的核心武器是 JavaScript，如今的网页客户端脚本几乎全是 JavaScript

攻击者只需要做一件事：想办法把一行 JavaScript 塞进网页里。 塞进去之后，浏览器会自动帮忙执行

XSS的分类

反射型

恶意代码在 URL 里 → 发给服务器 → 服务器没过滤，直接嵌到返回页面里 → 浏览器执行。

特征： 一次性的。骗一个人点一次链接，就只能打这一个人。攻击者需要把链接发出去，受害者必须点进来才会中招。

简单说： 服务器把 URL 里的东西原样吐回来了，浏览器当代码跑了。

存储型

恶意代码提交到服务器 → 存进数据库 → 别人访问这个页面 → 服务器从数据库取出，嵌进页面 → 所有人浏览器都执行。

关键特征： 永久性的。存一次，谁来看谁就执行。不需要骗人点链接，正常使用网站的人都会中招。这是最危险的一种

所以： 毒存服务器里了，谁来谁中招。

DOM 型

恶意代码在 URL 的 # 后面（浏览器不发给服务器）→ 服务器正常返回页面 → 页面自己的前端 JS 从 URL 里取出恶意内容，直接写进页面 → 浏览器执行。

关键特征： 服务器全程不知情。恶意代码根本没到过服务器——浏览器自己完成了”取出来 → 写进页面 → 执行”的全过程。后端无论怎么过滤都挡不住，因为代码根本不走后端。

所以： 跟服务器没关系，前端 JS 自己把 URL 里的毒掏出来咽了。
