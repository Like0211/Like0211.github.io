  • 不能点 → onclick 不触发

所以要想办法让 hidden 元素”活过来”

<input> 标签的 type 属性

HTML 里 <input> 是一个”输入框”标签，但它长什么样、怎么用，由 type 属性决定。

常见的 type 值：

type 值 显示效果
type="text" 普通文本框（能看见，能打字）
type="password" 密码框（输入显示成 ••••）
type="checkbox" 复选框
type="radio" 单选按钮
type="submit" 提交按钮
type="button" 普通按钮
type="hidden" 隐藏字段（页面上看不见）

HTML 标签中，如果同一个属性写了两次，浏览器只认第一个，后面的会被忽略。

所以目标让HTML变成这样：

<input name="t_sort" value="1" type="text" onclick="alert()" type="hidden">

所以输入&t_sort=1" type="text" onclick="alert()

t_ref ref Referer 的缩写 ✅

t_ref 里的 ref 就是 Referer 的简写。

Referer 是什么？

Referer 是一个 HTTP 请求头，告诉服务器：“我是从哪个页面点过来/跳过来的”。

既然 t_ref 的值可能来自 Referer 头，那就伪造一个 Referer 头发过去，看它会不会出现在 value 里。

所以这关需要在 Referer 请求头里放 payload。

Referer 就是”上一页地址”，是浏览器自动附带的一个请求头。这关的服务器把这个头的值读出来塞进了隐藏输入框 —— 而我们可以随意伪造这个头。

“伪造”其实就是在请求里自己加一行 Referer 文本。浏览器发请求前，你把内容改掉，就叫伪造。

这里使用burp suite

开代理，开拦截

在请求里面加上这句Referer: " type="text" onmouseover="alert(1)"

然后放行，关拦截

UA = User-Agent，中文叫”用户代理”。

拆开看：

  • Agent = 代理、代理人、代表

浏览器就是你派出去访问网站的”代理人”。网站问”你是谁？”，浏览器就报上这串名号：

“Mozilla/5.0 (Windows NT 10.0…) Firefox/153.0”

意思是：我是 Firefox 浏览器，跑在 Windows 10 上。这串自我介绍就叫 User-Agent，简称 UA。

所以这关的字段名叫 t_ua，就是提示：改 User-Agent 头

level 15

查看源码

<html ng-app> 这一行是告诉 AngularJS：”这个页面归你管了”。（ng-app 是 Angular 的”开工标记”）

<script src="angular.min.js"></script> 引入一个叫 AngularJS 的前端框架库（v1.2.0，很老）。

发现本题的关键一行 <span class="ng-include:1.gif"></span>

ng-include 是 AngularJS 的指令，意思是：把你给的地址当成”模板”加载进来。你 URL 里的 src 参数，会被原样塞进 ng-include: 后面。

所以思路是：让 ng-include 去加载一个能反射我们代码的页面

AngularJS 是什么？

可以把它理解成：一个帮你”自动干活”的网页工具。

普通网页是”死的”——HTML 写什么就显示什么。而 AngularJS 会扫描页面，看到某些特殊标记，就自动执行对应的动作。

这些特殊标记都长一个样，叫指令（directive），特点是以 ng- 开头。比如：

指令 作用
ng-app “这个区域我接管了”
ng-include “去某个网址取一段 HTML，塞到我这个位置”
ng-bind “把某个变量显示出来”

<span class="ng-include:1.gif"></span>的意思就是

“Angular ，请你把* 1.gif 这个地址的内容，加载进来填到 <span> *里。”

AngularJS 支持把指令写在 class 里，格式是：ng-include:表达式

冒号后面的内容，会被 Angular 当成”表达式”去求值，求值的结果就是它要去加载的网址。

这就是关键：1.gif 不是普通的字符串，而是代码表达式。

  • 如果你写 'level2.php'（带单引号）→ 这是一段”字符串”，求值结果是 level2.php → 正常
  • 如果你写 1.gif（不带引号）→ Angular 把它当 JS 代码去算：数字 1 的属性 gif → 算不出来，报错，啥也不加载

所以默认页面里 ng-include:1.gif 其实是没正常工作的

服务器做的事很简单：把URL 里 src= 后面的内容，原样填进 HTML 的 ng-include: 后面。

访问 ?src='level2.php'，响应就变成这样，同时level2的页面也出现

level2的 keyword 参数会被反射进页面正文，

如果 keyword 里放的是一段 HTML 标签，比如 keyword=<img src=x onerror=alert(1)>

这个被 level2 输出到了 <h2> 这个位置：<h2>没有找到和&lt;img src=x onerror=alert(1)&gt;相关的结果.</h2>

level2 在 h2 这个位置把尖括号转义了，所以 img 变成了一段纯文字，根本不是图片元素——自然就没有”加载失败”这回事。

但 level2 还有第二个反射点，就是那个 <input> 的 value，这里是不转义的。所以我们用 "> 先把 value 属性闭合、把 input 标签撑破，img 就能作为真正的标签出来：

所以keyword = "><img src=x onerror=alert(1)>就可以

最终 src='level2.php?keyword="><img src=x onerror=alert(1)>'

level 16

所以这关的结构特别简单：一个直来直去的反射点,你传什么，它就在 <center> 里显示什么

上一关我们学到，反射点不能只看”能不能显示”，还要看它是不是原样显示。

传 test 这种无害文字，当然是原样的。但如果传 <img src=x onerror=alert(1)> 呢？会不会被动手脚？

尝试传一个 img 标签：

发现所有空格都变成了 &nbsp;

&nbsp 是什么?

&nbsp 是一个 HTML 实体，它的含义是”不换行空格“（Non-Breaking Space）。

浏览器在显示文字时，看到 &nbsp 会把它渲染成一个空格的样子。

但是——在 HTML 标签内部，浏览器解析标签时，不把 &nbsp 当成分隔符。它只是一个普通字符，和字母 a、b 一样。

由于浏览器在解析 HTML 标签时，换行符和空格是等价的。

所以把 payload 里的空格，全部换成换行符！

在 URL 里，换行符用 %0a 表示

所以注入?keyword=<img%0asrc=x%0aonerror=alert(1)>
