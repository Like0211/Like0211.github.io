3.PHP 代码逐行详解

  • __FILE__：PHP 魔术常量，指当前文件完整路径（此处就是 source.php）
  • highlight_file()：把文件内容高亮输出到页面
  • 作用：这就是我们能直接看到源码的原因（源码泄露）
  • 关联数组：键 "source"/"hint"，值 "source.php"/"hint.php"
  • 注意：后面用 in_array($page, $whitelist)，默认比较的是”值”（不是键）
  • 所以真正有效的白名单值是：source.php、hint.php

第一个判断

  • isset($page)：变量已设置且不为 null
  • is_string($page)：必须是字符串
  • 不满足 → 输出 “you can’t see it” 并返回 false（阻止包含）

第二个判断

  • in_array($a, $b)：检查 $a 的值是否在数组 $b 的值中
  • 只有 $page 完全等于 source.php 或 hint.php 才通过

第三个判断（? 截断匹配）——漏洞关键

逐个函数解释：

函数 作用 类比
mb_strpos($a, '?') 返回 ? 在字符串 $a 中第一次出现的位置（下标从 0 开始） 找到刀口位置
$page . '?' 在字符串末尾追加一个 ? 防止没有 ? 时函数报错
mb_substr($a, 0, $n) 从第 0 位开始截取 $n 个字符 切下前半段
in_array(...) 判断前半段是否在白名单里 检查切下来的部分

这段的逻辑：取 $page 中第一个 ? 之前的内容，判断是否等于 source.php 或 hint.php。

这就是漏洞核心：校验只看 ? 前面的部分，但后面 include 用的是整个字符串。

第四个判断（URL 解码后再截断）

  • urldecode()：URL 解码一次（把 %3f 还原成 ?）
  • 然后重复”取 ? 前内容 + 白名单匹配”
  • 这是为了防”把 ? 编码后绕过”的情况

漏洞触发点

  • $_REQUEST['file']：从请求中读取名为 file 的参数（GET/POST/Cookie 均可）
  • 三个条件同时满足 → 执行 include
  • include 会把文件内容当作 PHP 代码执行；如果包含的是 .php 文件则执行代码，如果是普通文件则原样输出内容
  • 这里 include 的参数完全来自用户输入，且没有做任何过滤 → 文件包含漏洞

6.最终 Payload

Q&A

Q1：为什么先写 source.php？

因为漏洞代码在 source.php 里。必须先访问这个脚本，才能触发它内部的 include。它是漏洞入口。

Q2：../../../../../../ 是什么？

目录穿越。.. 表示上一级目录。多个 ../ 连续向上跳，跳出 Web 根目录（如 /var/www/html/），到达 flag 文件所在的上层目录。层数写多了不报错（到根目录后再跳仍在根目录），写少了才可能失败。

Q3：为什么要写 hint.php 而不是别的？

因为 hint.php 在白名单里。checkFile 只检查第一个 ? 之前的内容是不是白名单值，所以必须用一个白名单里的文件名打头。source.php 其实也行，只是 hint.php 同时承担了”给提示”的角色，更自然。

Q4：%3f 和 ? 有什么区别？

%3f 是 ? 的 URL 编码。

  • URL 本身的 ?：分隔”路径”和”参数”（在 source.php 后面那个）
  • 我们想要的 ?：出现在参数值内部，用来截断校验
  • 用 %3f 编码后传输，PHP 收到时解码还原成真正的 ?，既避免混淆，又能正常工作

2.Include

文件包含题

为什么 ?file=flag.php 暗示文件包含？

  1. 参数名就叫 file
    file 是很多开发者习惯使用的参数名，用来指定要包含的文件。常见的还有 page、include、path、template、url 等。这些名字都可能是文件包含的入口。

  2. 传入了文件名
    file=flag.php 中，给参数传的是一个文件名，说明服务器端很可能把这个值直接放到了 include() 或 require() 等函数里，比如：

    这样就造成了文件包含漏洞。

用 php://filter 拿到 flag

即使我们可以包含 flag.php，直接访问 ?file=flag.php 可能看不到 flag，因为：

  • flag.php 里可能只是定义了一个变量（如 $flag = "DASCTF{...}";）但没有输出。
  • 或者服务器执行了 PHP 代码，但输出被屏蔽了。

这时候我们可以使用 PHP 的流封装器 php://filter，它可以在文件被包含之前，对文件内容进行编码处理，然后再输出，而不是直接执行 PHP 代码。

常用的 payload：

它的工作原理：

  • php://filter 是 PHP 提供的一种流，可以附加各种过滤器。
  • convert.base64-encode 是一个过滤器，作用是把文件内容转换成 base64 编码。
  • resource=flag.php 指定要读取的文件。

当这个 URL 被服务器执行时，include() 会尝试包含这个“流”。由于过滤器的作用，flag.php 的源代码会被 base64 编码后输出，而不是被执行。这样我们就拿到了 flag.php 的源码（以 base64 形式），解码后就能看到 flag。

本题直接访问 url/?file=php://filter/convert.base64-encode/resource=flag.php直接得到base64码解码即可
